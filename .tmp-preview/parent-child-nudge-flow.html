3. What #500 changed ★ new

★ A. Stale-wait diagnostic wake

When a child terminally completes under a newer assignment than the parent wait references, the normal wait update can't match — previously a silent infinite hold. Now appendChildLifecycleNotification() emits a second report alongside the real result:

  • kind: blocked, wakeReason: assignment-blocked, id assignment-stale:<child>:<waitAssignment>
  • Marks the stale wait entry blocked (never fakes success) and coalesces into the same tail batch
  • Parent wakes immediately (blockers bypass waits) with both the real result and revise-the-wait guidance

decider.ts:405–580 · helper staleChildWaitAssignments() in childFollowUp.ts:58

★ B. Filter + reason precedence

  • evaluateChildFollowUp() keeps assignment-stale: diagnostics instead of dropping them as assignment mismatches (childFollowUp.ts:92)
  • childWaitBlockReason() reports needs attention for already-recorded failures/blockers even if the child was since reassigned or archived (childFollowUp.ts:42)
  • Web ChildFollowUpPanel inherits the clearer message (display-only, no logic change)

★ C. Parent drain on child queue events

QueuedTurnReactor now also drains the parent when a child emits queued-turn-created / updated (previously only meta-updated / archived / deleted / decoupled), so assignment changes on a child re-evaluate a waiting parent instead of depending on a later unrelated event. No new timers or polling. QueuedTurnReactor.ts:433

4. The original bug, walked through

Parent spawns 4 helpers (automatic) + set_child_wait(all × 4)
  → 4 × turn.diff.complete → 4 × result-available expected
  → observed: all children done, parent stuck on “Waiting for 1 child”

Stranding required just ONE of:
  R1  4th completion dropped by the fence (stale turn / pending interaction /
      child-has-unfinished-children guard) → no report at all
  R2  batch spawned notify-only, or only progress reports → correctly no wake
  R3  one child reassigned → wait references old assignmentId → hold forever ★ fixed
  R4  Stop/paused, active turn, approval/input, collectUntil, or user message
      (“check on helper threads” runs BEFORE the nudge) → held, not lost
